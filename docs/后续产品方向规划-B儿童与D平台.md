# VoiceCanvas · 后续产品方向规划

> 主题：B. 儿童语音绘画工具 + D. AI 语音绘图平台
> 日期：2026-06-16
> 用途：作为当前 PRD 之后的中期产品方向补充文档

---

## 1. 背景

当前 `PRD.md` 已经把 VoiceCanvas 的主方向调整为「面向 C 端家庭的 AI 儿童创作产品」。这是一个更容易验证需求、更容易传播、也更适合现有能力结构的方向。

但从中长期看，产品还存在另一条自然延伸路线：把 VoiceCanvas 做成一个更通用的「AI 语音绘图平台」，服务更广泛的用户群体，而不只局限于儿童和家长。

因此，后续讨论聚焦两个方向：

1. **B 方向：儿童语音绘画工具**
2. **D 方向：AI 语音绘图平台**

这两个方向并不冲突，但**不能在产品层同时做成两个完全不同的叙事**。更合理的做法是：

- **短中期用 B 方向做市场切入和体验打磨**
- **中长期沉淀 D 方向的平台能力和开放能力**

---

## 2. 方向 B：儿童语音绘画工具

### 2.1 核心定位

一句话定义：

> 孩子开口描述，AI 帮他把脑海中的故事一笔笔画出来。

这个方向强调的不是“高精度绘图工具”，而是“低门槛表达工具”。用户不是来做专业设计，而是来完成表达、创作、讲故事和分享。

### 2.2 目标用户

- 3-8 岁儿童
- 家长
- 幼教老师 / 早教场景中的陪伴者

### 2.3 用户价值

- 孩子不会打字、不会画画，也能完成创作
- 家长可以把孩子的表达沉淀成作品
- 产品天然适合“讲故事 -> 生成画面 -> 分享”的家庭互动场景

### 2.4 最值得增加的功能

1. **连续语音创作**
   - “再加一朵云”
   - “把太阳变大一点”
   - “旁边再画一只小猫”

2. **儿童绘本模式**
   - 单页创作升级为多页连续故事
   - 每一页都能语音描述
   - 自动生成封面、标题、故事摘要

3. **语音故事模式**
   - 孩子先说故事
   - 系统自动拆成 3-5 个画面分页
   - 一键生成可翻页作品

4. **家长辅助能力**
   - 收藏孩子作品
   - 导出成长记录
   - 按日期、主题、节日整理

5. **儿童友好交互**
   - 更少文字
   - 更大按钮
   - 更多语音反馈和确认

### 2.5 商业化适配

这个方向适合：

- 订阅制
- 单次绘本导出付费
- 节日主题包 / 风格包
- 实体绘本打印

它的优点是传播强、故事感强、内容素材天然丰富。

## 3. 方向 D：AI 语音绘图平台

### 3.1 核心定位

一句话定义：

> 一个让用户通过自然语言和语音完成可视化创作的 AI 平台。

这个方向不再只服务儿童，而是把产品抽象成一种新的人机交互方式：**用语音驱动画布、图形和场景生成**。

### 3.2 目标用户

- 普通创作者
- 内容创作者
- 教师 / 演讲者 / 培训者
- 不擅长复杂设计软件，但需要快速表达画面的人

### 3.3 用户价值

- 相比传统设计工具，上手门槛低
- 相比纯文生图，过程更可控
- 相比纯几何画板，表达方式更自然

### 3.4 最值得增加的功能

1. **多轮编辑能力**
   - “把刚才那个圆放到左上角”
   - “把背景改成夜晚”
   - “删掉那只鸟”

2. **对象级理解**
   - 系统识别并维护“当前画面里有哪些对象”
   - 支持引用、替换、删除、变形

3. **模式切换**
   - 儿童模式
   - 通用创作模式
   - 演示草图模式

4. **模板化输出**
   - 海报草图
   - 故事版分镜
   - 课堂示意图
   - 贺卡与分享图

5. **开放接口能力**
   - 后续可提供 API / SDK
   - 支持第三方把“语音生成画面”能力接进自己的应用

### 3.5 商业化适配

这个方向更像平台产品，适合：

- Freemium + Pro 订阅
- API 调用计费
- 模板市场
- B2B 场景合作

但它的难点也更明显：用户面更广，产品边界更难守，容易失焦。

## 4. B 与 D 的关系

这两个方向不是二选一，而是：

- **B 是产品切入口**
- **D 是能力终局**

更具体地说：

### 4.1 为什么不能先做 D

如果一开始就把自己定义成“AI 语音绘图平台”，会遇到三个问题：

1. **用户太泛**
   - 谁都能用，往往等于没有明确的核心用户

2. **需求太散**
   - 儿童创作、教育表达、故事板、轻设计、无障碍工具都会混在一起

3. **路线太重**
   - 平台化往往要求编辑能力、对象系统、账号体系、模板系统、权限体系一起补齐

对当前阶段来说，这会明显拖慢验证速度。

### 4.2 为什么 B 更适合作为近期主线

儿童方向有几个现实优势：

- 用户场景清楚
- 分享内容更容易自然传播
- 当前“AI 一笔笔画出来”的体验和儿童创作高度契合
- 对“精准编辑”的要求比通用平台低，更适合先把基础体验做顺

### 4.3 为什么又必须保留 D 的能力视角

如果只把自己当儿童产品，后面会遇到天花板：

- 创作场景单一
- 单用户价值有限
- 商业模型容易依赖流量和内容运营

所以在产品叙事上先聚焦 B，但在能力设计上要逐步积累 D 需要的底层能力：

- 画面状态管理
- 对象识别与引用
- 多轮编辑
- 模板系统
- 导出与分享能力

## 5. 建议的产品策略

### 5.1 总策略

建议采用：

> **“儿童创作产品外壳 + 通用创作平台内核”**

外部讲法以儿童和家庭创作为主，内部能力建设则朝平台化推进。

### 5.2 路线拆分

#### 第一阶段：做强 B 方向体验

目标：先把“孩子开口就能连续创作并生成完整作品”这件事做透。

优先功能：

1. 多轮语音连续创作
2. 儿童绘本模式
3. 家长作品管理
4. 创作过程回放与分享
5. 更强的语音反馈与引导

#### 第二阶段：抽象 D 方向能力

目标：逐渐把儿童创作过程中沉淀出来的底层能力抽象出来。

优先功能：

1. 画布对象模型
2. 对象级编辑指令
3. 模板化创作模式
4. 通用创作入口

#### 第三阶段：验证平台化空间

目标：判断产品是否有机会从儿童创作工具扩展成更广义的语音创作平台。

验证方式：

1. 观察非儿童场景使用比例
2. 测试教师 / 内容创作者 / 轻设计用户的留存
3. 小范围验证模板化输出与 API 能力

---

## 6. 建议优先级

如果只看后续 1-2 个版本，我建议优先级如下：

### P0：必须尽快补齐

- 多轮连续语音编辑
- 作品回放
- 绘本分页创作
- 家长视角的作品整理与导出

### P1：明显增强产品差异化

- 故事自动分镜
- 儿童模式 / 通用模式切换
- 对象级简单编辑（增删改基础元素）
- 更强的语音反馈系统

### P2：平台化探索

- 模板市场
- 通用创作场景
- 第三方嵌入能力
- API / SDK

---

## 7. 结论

VoiceCanvas 后续最合理的路线，不是同时做两个产品，而是分层推进：

1. **对外，先坚定做儿童语音创作工具**
2. **对内，逐步把能力沉淀成 AI 语音绘图平台底座**

如果一句话总结：

> 先用儿童场景把产品做得有温度、有传播性、有真实使用场景；再把这些能力抽象成一个更大的语音创作平台。

因此，近期建议的产品主线是：

- 叙事上偏 **B**
- 能力上兼顾 **D**
- 节奏上 **先聚焦，后抽象**

这比直接追求“大而全的平台化”更稳，也更符合当前产品阶段。
